Buttons and actions

Button emphasis, destructive actions, and shared icon actions.

Buttons

Accessibility: Use native types and disabled states, stable accessible names, and visible keyboard focus. Color does not explain destructive behavior. Applications own action feedback and confirmation. APG button guidance.

Native submit, button, and reset types provide primary, secondary, and tertiary emphasis. Existing emphasis styles keep their text color on hover. Text and destructive actions below demonstrate the new optional treatments; their clicks only report local example state.

Shared close, clear, and remove actions

Use a named native button with data-barba-variant="icon" and data-barba-shape="icon". Add data-barba-size="compact" for a smaller face. Hide decorative icon SVGs from assistive technology. The accessible name describes the actual action; close, clear, remove, and destructive deletion have different meanings.

Prefer a concise aria-label for new icon-only buttons, such as “Clear item name”. A hidden text label remains a supported alternative; existing valid names need no migration. Keep ordinary buttons named by visible text. If an accessible name adds context, preserve the visible wording, preferably at the beginning, as in “Create category” for a button showing “Create”. Avoid competing naming sources because ARIA naming can override descendant text. See naming choices and the hidden-text alternative.

<button type="button" data-barba-variant="icon" data-barba-shape="icon"
  aria-label="Clear item name">
  <svg aria-hidden="true" focusable="false" width="20" height="20" viewBox="0 0 24 24">
    <path d="m6 6 12 12M18 6 6 18" fill="none" stroke="currentColor" stroke-width="2" />
  </svg>
</button>

Applications own visibility, disabled states, and focus transitions. Try clearing a field, removing a chip, or closing a dialog. See the shared icon-action markup and target guidance.
