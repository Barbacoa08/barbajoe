Chips

Use informational chips for labels, toggle buttons for filters, and a separate X for removing a selection. Short chips are 1.5rem high (24px at a 16px root). Labels wrap rather than truncate. Compact targets trade touch comfort for density; retain the larger close/clear targets elsewhere.

The remove X shares the close/clear background-only treatment, with a 2px inset that leaves the chip border visible. Removing a selection does not delete the category or saved item. These examples keep all changes local.

Inline forms and input actions

Use an inline-field wrapper for a visible standard-size, medium-weight label above an input-row. The input grows; Add wraps to the right when space runs out. An optional input-action groups a text input with its X. Ordinary stacked forms keep their existing appearance.

The X is our shared close/clear icon action: a native button with data-barba-variant="icon" and data-barba-shape="icon". It has a generous target, transparent resting face, a circular hover background inset by 2px, and a separate keyboard-focus outline. Its accessible name describes the action: “Clear item name” for an input, “Close dialog” for a modal. The icon is decorative; these actions do not delete saved data.

Dialogs

Both dialogs start at the same viewport-relative top offset. Short content leaves the footer at the minimum-height bottom. Long content grows to the viewport cap, then only its body scrolls. Footer order is Reset, Cancel, Submit. Submit validates and closes; Cancel or clicking outside closes without validation; Reset restores initial values and stays open. Closing does not reset the form.

Long dialog

Content-driven sizing

The dialog grows with its contents rather than reserving a fixed preferred height. Its minimum leaves space for a useful short form.

Viewport limits

The maximum is eighty percent of the visible viewport, with outer gutters retained on exceptionally short screens. The minimum shrinks when the viewport cannot accommodate it.
