Disclosures

Accessibility: Keep native details/summary semantics; avoid redundant roles, tabindex and aria-expanded. Required instructions must remain visible. MDN summary guidance.

Use details.disclosure to group optional settings, filters, or supporting information. Both variants use the same native disclosure markup and a full-width summary target. Keep essential instructions visible outside collapsed sections.

Place the label in disclosure-label, its title in disclosure-title, optional supporting text in disclosure-description, and the body in disclosure-content. A heading can carry both label and title classes. Choose its level for the page hierarchy; the class only normalizes its appearance.

These examples use native disclosure behavior: Enter or Space opens a focused summary, and multiple sections can stay open. Checkboxes and Reset work locally without saving. Put links and inputs in the body. Extra header actions must be siblings outside the summary with separate targets, as in the filled filter example below. Nest only when the content needs that hierarchy.

Both styles animate opening and closing when the browser supports the required CSS and reduced motion is not requested. Otherwise, panels open and close instantly. Closed content remains searchable after the closing transition. Compare animated and instant behavior.

These are recommendations, not restrictions. Both styles support the same content and native behavior. Chevrons point inward when collapsed and down when expanded, aligned with the title’s first line. Compare all disclosure states.

The summary target is at least 2.75rem high (44px at a 16px root size). Keyboard focus uses the library’s separate outline; hover and press tint the summary. The same panel treatment applies in both themes.

Use the native open attribute for an initially expanded section. Leave off the native name attribute to allow independent expansion. Do not add a button role, tabindex, or manually maintained aria-expanded to the summary. Applications own persistence and control behavior; no JavaScript is needed for opening and closing. If heading navigation inside a summary matters, check it with your target assistive technology, or place a section heading outside the disclosure. See summary heading guidance.

Unclassed details keeps the browser’s native appearance. App layouts own spacing between panels; the examples use a grid gap. Customize through the existing color, spacing, and radius tokens or scoped application CSS.

Application responsibilities: Keep the visible summary current in both states: show “All items” when neither group is restricted, otherwise join selected labels with middle dots in stable group order. Native aria-pressed buttons expose each selection; this example adds no duplicate live announcement. If filtering changes a results list, follow the result-status guidance for a persistent live region and concise counts.

Clear action: The X is a named button outside summary in the DOM, positioned inside the filled header before the chevron. Reserve its target space so it cannot cover the title or chevron. Clear and the chevron stay beside the first title line while the selected labels wrap together below it. Clear must not toggle expansion; focus summary before hiding the X. When expanded, keyboard navigation reaches Clear after the body controls; when collapsed, directly after summary. Empty groups select their “All” action. Applications own filtering, persistence, result announcements, and focus transitions.

Example-only code: The specimen-filter-* classes provide inline/wrapping summary text, field-group spacing, and sibling clear-action placement. They are not library APIs. disclosure-filters.js shares local selection/reset behavior with the state gallery; the CSS package contains no JavaScript. Reuse the public disclosure and chip hooks, then implement your application's layout and state.

Composition and accessibility

  • Show “All items” when neither group is restricted. Otherwise, join selected labels with middle dots in stable group order. The whole summary may wrap beneath the title; keep Clear and the chevron on its first line. Do not add category prefixes when the labels already explain themselves.
  • Clear is a named native button outside summary in the DOM, visually positioned in a reserved header slot. Its target must not cover the title or chevron. It clears both groups, returns focus to summary before hiding, and leaves expansion unchanged. In the keyboard order, it follows the visible filter controls when expanded and follows summary directly when collapsed.
  • “All stores” and “All categories” reset only their own group. Native buttons use aria-pressed; closing preserves selections. Native summary exposes expansion without a duplicate role or ARIA state. See MDN summary guidance.
  • These controls add no live announcement duplicating pressed-state feedback. Applications own actual filtering, persistence, and concise result messages. Keep a result region mounted before updates; follow the catalog's live-region timing and naming guidance.
  • specimen-filter-* and specimen-disclosure-* are example-only layout classes. disclosure-filters.js supplies one shared synthetic renderer/controller for the working example and state gallery. Neither the layout hooks nor scripts are public library APIs or shipped package code.
  • Verify target separation, native keyboard behavior, focus after clearing, long and translated labels, narrow layouts, real zoom, and actual screen-reader speech in your application. Browser assertions do not establish spoken output or physical-device behavior.
